# 子智能体分工模板（大批量重命名）

会话超过 ~15 条、或单条历史很长时，单线程读会撑爆上下文。按下面的方式切分。

## 一、先导出

```bash
python <skill>/scripts/qoder_sessions.py rename --export --filter "status = active" --out ./exp
```

产出 `./exp/<sid8>.txt` + `./exp/index.json`。`index.json` 里有每条的 `bytes`、`messages`、`user_turns`，用它来配平。

## 二、按体积切片

目标：**每片 60–90 KB、6–9 条**。不要按条数平均切——一条 169 消息的会话可能比十条小会话还大。

```
片 1: 91KB 的那一条 + 两三条小的
片 2: 40KB + 36KB
片 3: 33KB + 29KB + 20KB
...
```

单条超过 90 KB 的，让它独占一片。

## 三、派活提示词（逐片各发一份）

```
你是会话命名专家。通读整段对话的完整历史后再命名，不能只看开头。

输入目录：<绝对路径>/exp/
本片文件：a.txt, b.txt, c.txt（都要完整读完，必要时分段 Read）

背景：这些会话现有的标题只反映「首条用户消息」，往往漏掉真正的主线。
你要判断：用户最初想做什么 → 中途遇到什么 → 最后实际交付了什么。
若中途转向，以占篇幅最大或最终解决的那条主线命名。

标题规则：
1. 简体中文，8–22 个汉字；SSH/RDP/RAID5/NAS/WinGet 等技术名词保留原文，与中文之间加半角空格。
2. 结构优先「动作 + 具体对象」，要能和同目录下其他会话区分。
3. 禁止引号、书名号、句号、问号、换行、文件路径、代码。
4. 同一批内不得出现含义重复的标题。

输出：Write 到 <绝对路径>/titles_片N.json
[{"sid":"完整SESSION_ID","new_title":"标题","why":"一句话依据"}]
```

## 四、回收与合并

1. 检查每片 JSON 能否 `json.load`、条数是否与指派一致。
2. 合并成一个 `titles.json`。
3. 交叉校验：
   - 同一 `cwd` 下的标题是否互斥（尤其「工具包」「闲鱼」「RDP」这类同主题群）。
   - 是否有两条标题语义几乎相同。
   - 长度是否越界。
4. 先干跑：

```bash
python <skill>/scripts/qoder_sessions.py rename --import titles.json
```

5. 核对清单无「与现标题相同」「跳过」异常后落盘：

```bash
python <skill>/scripts/qoder_sessions.py rename --import titles.json --apply
```

## 五、常见问题

| 现象 | 处理 |
|---|---|
| 子智能体只读了文件开头 | 提示词里强调「必须完整读完，长文件分段 Read」 |
| 多条标题雷同 | 合并阶段人工改，或在提示词里点名要求区分 |
| 用了现有标题的措辞 | 明确要求「不得照抄 CURRENT_TITLE」 |
| 漏条 | 用 index.json 的 sid 列表做差集核对 |

## 六、实测数据参考

27 条会话、完整历史合计 409 KB，切 6 片（每片 30–92 KB），6 个子智能体并行，端到端约 1 分钟。
其中最长一条 169 消息 / 57 轮、91 KB，独占一片。
